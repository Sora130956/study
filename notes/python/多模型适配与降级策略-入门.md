# 多模型适配与降级策略 - 入门教程

## 第 1 节：它是什么（一句话 + 一句类比）

**多模型适配**：用一层薄抽象统一不同 LLM 供应商（OpenAI、Anthropic、DeepSeek）的调用接口，通过配置文件切换模型，无需修改业务代码。

**降级策略**：主模型调用失败时（如服务故障、限流），自动切换到备用模型，保证服务可用性。

**类比**：

- 多模型适配像电器的通用插座转换器——无论是美标、欧标还是英标插头（不同 API），都能插到同一个接口上工作。
- 降级策略像餐厅的备用食材——主厨推荐的澳洲牛排卖完了（主模型挂了），自动换成新西兰牛排（备用模型），顾客照样能吃上牛排。

## 第 2 节：它解决什么问题 / 为什么需要它

### 不用多模型适配会怎样？

假设你直接调用 OpenAI API，业务代码里到处都是：

```python
# 散落在各处的 OpenAI 专用代码
from openai import AsyncOpenAI
client = AsyncOpenAI(api_key="sk-...")

async def summarize(text):
    response = await client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": f"Summarize: {text}"}]
    )
    return response.choices[0].message.content

async def translate(text):
    response = await client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": f"Translate to Chinese: {text}"}]
    )
    return response.choices[0].message.content
```

**痛点**：

1. **供应商锁定**：换成 Anthropic 或 DeepSeek，需要改遍所有调用点（`client.chat.completions.create` → `client.messages.create`）。
2. **成本优化困难**：想对简单任务用便宜模型（GPT-3.5）、复杂任务用贵模型（GPT-4），需要每处硬编码判断。
3. **测试环境切换麻烦**：开发时想用 DeepSeek 省钱，生产用 GPT-4，需要维护两套代码或满屏 `if ENV == "prod"`。

**问题根源**：业务逻辑与供应商 SDK 强耦合，没有抽象层隔离。

***

### 不用降级策略会怎样？

假设只用一个模型，没有备用方案：

```python
async def call_llm(text):
    return await openai_client.chat.completions.create(...)  # 唯一入口
```

**痛点**：

1. **服务雪崩**：OpenAI 故障时（如 2023 年 11 月大规模宕机），你的应用完全不可用，用户看到一片报错。
2. **限流硬失败**：触发 429 限流后，直接向用户返回错误，没有缓冲空间。
3. **无法平衡成本与质量**：不能"主模型失败时用便宜但能用的模型兜底"。

**问题根源**：单点依赖，没有容错机制。

***

### 经典应用场景

- **多模型适配**：SaaS 产品支持用户自选模型、多云部署、A/B 测试不同模型效果。
- **降级策略**：客服机器人（主模型挂了也要保证基本回复）、批量任务（部分失败不能影响整体进度）。

## 第 3 节：读下去之前，先搞懂这些概念

| 术语                  | 大白话解释                          | 最小示例                             | 对应章节  |
| ------------------- | ------------------------------ | -------------------------------- | ----- |
| 抽象层（Adapter）        | 统一不同供应商的接口差异，业务代码只调用抽象层        | `adapter.chat(prompt)`           | 示例 1  |
| 协议（Protocol）        | Python 的"接口"定义，不强制继承但要求实现相同方法  | `class MyAdapter(Protocol): ...` | 示例 1  |
| 工厂模式                | 根据配置参数（如模型名）自动创建对应的适配器实例       | `create_adapter(model="gpt-4")`  | 示例 2  |
| 降级（Fallback）        | 主操作失败后，按优先级尝试备用操作，直到成功或全部失败    | `try 主模型 except 切备用`             | 示例 3  |
| 熔断（Circuit Breaker） | 记录失败次数，连续失败 N 次后暂时跳过该模型，避免浪费时间 | `if failures > 3: skip`          | 第 6 节 |

**术语速查表**：如果你熟悉设计模式和异常处理，可以直接跳到第 4 节。

## 第 4 节：从最简单的代码示例开始

### 示例 1：最小可运行版本 - 统一接口抽象

```python
from typing import Protocol
from openai import AsyncOpenAI
from anthropic import AsyncAnthropic

# 定义统一接口（所有适配器必须实现这个方法）
class LLMAdapter(Protocol):
    async def chat(self, prompt: str, model: str) -> str:
        """统一的聊天接口"""
        ...

# OpenAI 适配器
class OpenAIAdapter:
    def __init__(self, api_key: str):
        self.client = AsyncOpenAI(api_key=api_key)
    
    async def chat(self, prompt: str, model: str = "gpt-3.5-turbo") -> str:
        """OpenAI 专用调用逻辑"""
        response = await self.client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

# Anthropic 适配器
class AnthropicAdapter:
    def __init__(self, api_key: str):
        self.client = AsyncAnthropic(api_key=api_key)
    
    async def chat(self, prompt: str, model: str = "claude-3-haiku-20240307") -> str:
        """Anthropic 专用调用逻辑"""
        response = await self.client.messages.create(
            model=model,
            max_tokens=1024,
            messages=[{"role": "user", "content": prompt}]
        )
        return response.content[0].text

# 业务代码（与具体供应商解耦）
async def summarize_text(adapter: LLMAdapter, text: str) -> str:
    """摘要功能，接受任意适配器"""
    prompt = f"Please summarize the following text:\n\n{text}"
    return await adapter.chat(prompt, model="gpt-3.5-turbo")  # 模型名统一管理

# 使用示例
import asyncio

async def main():
    # 方式 1：用 OpenAI
    openai_adapter = OpenAIAdapter(api_key="sk-xxx")
    result1 = await summarize_text(openai_adapter, "Long article...")
    
    # 方式 2：用 Anthropic（业务代码不变，只换适配器）
    anthropic_adapter = AnthropicAdapter(api_key="sk-ant-xxx")
    result2 = await summarize_text(anthropic_adapter, "Long article...")

asyncio.run(main())
```

**逐段解读**：

1. **`LLMAdapter`** **Protocol**：
   - 定义统一接口：所有适配器必须有 `chat(prompt, model)` 方法。
   - `Protocol` 是 Python 的"鸭子类型"接口，不强制继承，但 IDE 会检查方法签名。
2. **`OpenAIAdapter`** **和** **`AnthropicAdapter`**：
   - 各自封装供应商 SDK 的调用细节。
   - OpenAI 用 `chat.completions.create`，Anthropic 用 `messages.create`，但对外都是 `chat` 方法。
   - **关键**：`model` 参数在适配器内部设置默认值，业务代码可以不关心具体模型名。
3. **业务代码** **`summarize_text`**：
   - 参数类型是 `LLMAdapter`，接受任何符合接口的适配器。
   - 调用时不需要知道底层是 OpenAI 还是 Anthropic。

**这一步你得到了什么**：业务逻辑与供应商解耦，切换模型只需改适配器创建代码，无需动业务函数。

### 示例 2：加一个真实小需求 - 配置文件驱动的工厂模式

```python
import os
from typing import Literal

# 配置类（从环境变量或配置文件读取）
class LLMConfig:
    def __init__(self):
        self.provider: Literal["openai", "anthropic", "deepseek"] = os.getenv("LLM_PROVIDER", "openai")
        self.api_key: str = os.getenv("LLM_API_KEY", "")
        self.model: str = os.getenv("LLM_MODEL", "gpt-3.5-turbo")

# DeepSeek 适配器（兼容 OpenAI SDK）
class DeepSeekAdapter:
    def __init__(self, api_key: str):
        self.client = AsyncOpenAI(
            api_key=api_key,
            base_url="https://api.deepseek.com"  # 兼容 OpenAI SDK，只改 base_url
        )
    
    async def chat(self, prompt: str, model: str = "deepseek-chat") -> str:
        response = await self.client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": prompt}]
        )
        return response.choices[0].message.content

# 工厂函数：根据配置创建适配器
def create_adapter(config: LLMConfig) -> LLMAdapter:
    """根据 provider 自动创建对应适配器"""
    if config.provider == "openai":
        return OpenAIAdapter(api_key=config.api_key)
    elif config.provider == "anthropic":
        return AnthropicAdapter(api_key=config.api_key)
    elif config.provider == "deepseek":
        return DeepSeekAdapter(api_key=config.api_key)
    else:
        raise ValueError(f"Unsupported provider: {config.provider}")

# 业务代码（完全配置驱动）
async def main():
    config = LLMConfig()  # 从环境变量读取
    adapter = create_adapter(config)  # 自动创建适配器
    
    # 业务逻辑不关心用哪个供应商
    result = await adapter.chat("Translate 'hello' to Chinese", model=config.model)
    print(result)

# 使用时只需设置环境变量
# export LLM_PROVIDER=deepseek
# export LLM_API_KEY=sk-xxx
# export LLM_MODEL=deepseek-chat
asyncio.run(main())
```

**逐段解读**：

1. **`LLMConfig`** **类**：
   - 从环境变量读取配置：`LLM_PROVIDER`（供应商）、`LLM_API_KEY`、`LLM_MODEL`。
   - 默认值：`openai` + `gpt-3.5-turbo`。
2. **`create_adapter`** **工厂函数**：
   - 根据 `config.provider` 分支创建对应适配器。
   - 新增供应商时只需加一个 `elif` 分支，业务代码零改动。
3. **DeepSeek 适配器**：
   - DeepSeek 兼容 OpenAI SDK，只需修改 `base_url`。
   - 这是"薄抽象"的典型：不重复造轮子，直接复用 SDK。
4. **配置驱动的好处**：
   - 开发环境：`LLM_PROVIDER=deepseek`（便宜）。
   - 生产环境：`LLM_PROVIDER=openai`（质量高）。
   - 切换无需改代码，只改环境变量。

**这一步你得到了什么**：通过配置文件切换模型，代码零修改，支持 3 个供应商。

### 示例 3：贴近项目的样子 - 自动降级策略

```python
import asyncio
from typing import Optional
from dataclasses import dataclass

@dataclass
class ModelConfig:
    """单个模型的配置"""
    provider: str
    model: str
    api_key: str
    priority: int  # 优先级，1 最高

class FallbackLLM:
    """支持自动降级的 LLM 调用器"""
    def __init__(self, models: list[ModelConfig]):
        # 按优先级排序（priority 越小越优先）
        self.models = sorted(models, key=lambda m: m.priority)
        self.adapters = [self._create_adapter(m) for m in self.models]
    
    def _create_adapter(self, config: ModelConfig) -> LLMAdapter:
        """创建适配器（复用示例 2 的工厂函数）"""
        if config.provider == "openai":
            return OpenAIAdapter(api_key=config.api_key)
        elif config.provider == "anthropic":
            return AnthropicAdapter(api_key=config.api_key)
        elif config.provider == "deepseek":
            return DeepSeekAdapter(api_key=config.api_key)
        else:
            raise ValueError(f"Unknown provider: {config.provider}")
    
    async def chat(self, prompt: str, max_retries: int = 3) -> dict:
        """
        依次尝试所有模型，直到成功
        返回：{"result": str, "model_used": str, "attempts": int}
        """
        last_error: Optional[Exception] = None
        
        for attempt, (model_config, adapter) in enumerate(zip(self.models, self.adapters), start=1):
            try:
                print(f"尝试第 {attempt} 个模型: {model_config.provider}/{model_config.model}")
                result = await adapter.chat(prompt, model=model_config.model)
                
                return {
                    "result": result,
                    "model_used": f"{model_config.provider}/{model_config.model}",
                    "attempts": attempt,
                    "success": True
                }
            
            except Exception as e:
                print(f"❌ {model_config.provider} 失败: {str(e)[:50]}")
                last_error = e
                
                # 如果是最后一个模型，直接抛异常
                if attempt >= len(self.models):
                    break
                
                # 否则继续尝试下一个模型
                await asyncio.sleep(1)  # 短暂延迟避免瞬间失败
        
        # 所有模型都失败
        return {
            "result": None,
            "model_used": None,
            "attempts": len(self.models),
            "success": False,
            "error": str(last_error)
        }

# 使用示例
async def main():
    # 配置多个模型（优先级递增）
    models = [
        ModelConfig(provider="openai", model="gpt-4", api_key="sk-xxx", priority=1),          # 主模型
        ModelConfig(provider="anthropic", model="claude-3-haiku", api_key="sk-ant-xxx", priority=2),  # 备用 1
        ModelConfig(provider="deepseek", model="deepseek-chat", api_key="sk-ds-xxx", priority=3)     # 备用 2
    ]
    
    llm = FallbackLLM(models)
    
    # 调用时自动降级
    response = await llm.chat("Explain quantum computing in simple terms")
    
    if response["success"]:
        print(f"✅ 成功！使用模型: {response['model_used']}, 尝试次数: {response['attempts']}")
        print(f"结果: {response['result'][:100]}...")
    else:
        print(f"❌ 所有模型都失败: {response['error']}")

asyncio.run(main())
```

**逐段解读**：

1. **`ModelConfig`** **数据类**：
   - 包含单个模型的完整配置：供应商、模型名、API key、优先级。
   - `priority` 用于排序：1 = 主模型，2 = 备用 1，3 = 备用 2。
2. **`FallbackLLM`** **类**：
   - 初始化时按优先级排序，创建所有适配器。
   - `chat` 方法遍历适配器，逐个尝试。
3. **降级逻辑**：
   - `for` 循环按优先级尝试每个模型。
   - 成功立即返回，记录使用的模型和尝试次数。
   - 失败时捕获异常，打印日志，继续下一个。
   - 所有模型都失败时返回包含错误信息的字典。
4. **延迟重试**：
   - `await asyncio.sleep(1)`：模型切换间短暂延迟，避免瞬间故障导致所有模型都失败（如网络抖动）。

**这一步你得到了什么**：一个生产级的降级调用器，主模型挂了自动切备用，记录尝试次数和使用的模型。

## 第 5 节：最小可用的实际用法（生产场景模板）

以下是在真实项目中集成的完整示例：

```python
# config.py - 配置管理（必须）
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    # 主模型配置（必须）
    primary_provider: str = "openai"
    primary_model: str = "gpt-4"
    primary_api_key: str
    
    # 备用模型配置（可选，建议配置）
    fallback_provider: str = "deepseek"
    fallback_model: str = "deepseek-chat"
    fallback_api_key: str
    
    # 降级开关（可选）
    enable_fallback: bool = True
    
    class Config:
        env_file = ".env"

# llm_service.py - LLM 服务层（必须）
from fallback_llm import FallbackLLM, ModelConfig

class LLMService:
    """全局 LLM 服务单例"""
    def __init__(self, settings: Settings):
        models = [
            ModelConfig(
                provider=settings.primary_provider,
                model=settings.primary_model,
                api_key=settings.primary_api_key,
                priority=1
            )
        ]
        
        # 如果启用降级，添加备用模型（推荐）
        if settings.enable_fallback:
            models.append(
                ModelConfig(
                    provider=settings.fallback_provider,
                    model=settings.fallback_model,
                    api_key=settings.fallback_api_key,
                    priority=2
                )
            )
        
        self.llm = FallbackLLM(models)
    
    async def chat(self, prompt: str) -> str:
        """业务代码调用的统一入口（必须）"""
        response = await self.llm.chat(prompt)
        
        if not response["success"]:
            raise RuntimeError(f"所有 LLM 模型调用失败: {response['error']}")
        
        # 记录使用的模型（可选，用于监控）
        print(f"📊 使用模型: {response['model_used']}, 尝试: {response['attempts']}")
        
        return response["result"]

# main.py - 应用入口（必须）
settings = Settings()  # 从 .env 加载配置
llm_service = LLMService(settings)

# 业务代码示例
async def summarize_article(article: str) -> str:
    prompt = f"Summarize this article:\n\n{article}"
    return await llm_service.chat(prompt)

# .env 文件配置（必须）
"""
# 主模型（必须）
PRIMARY_PROVIDER=openai
PRIMARY_MODEL=gpt-4
PRIMARY_API_KEY=sk-xxx

# 备用模型（建议配置）
FALLBACK_PROVIDER=deepseek
FALLBACK_MODEL=deepseek-chat
FALLBACK_API_KEY=sk-xxx

# 降级开关（可选）
ENABLE_FALLBACK=true
"""
```

**关键配置说明**：

1. **主备模型选择**（必须决策）：
   - 主模型：选质量最好但最贵的（如 GPT-4、Claude Opus）。
   - 备用模型：选便宜但能用的（如 GPT-3.5、DeepSeek、Llama）。
   - 原则：备用模型质量可降低，但不能完全不能用。
2. **降级开关**（按需配置）：
   - 开发环境：`ENABLE_FALLBACK=false`（单模型，方便调试）。
   - 生产环境：`ENABLE_FALLBACK=true`（多模型，保证可用性）。
3. **监控指标**（进阶，可先跳过）：
   - 记录每次调用使用的模型（`model_used`）和尝试次数（`attempts`）。
   - 统计主模型失败率：`fallback_rate = (attempts > 1 的次数) / 总次数`。
   - 设置告警：如果 `fallback_rate > 10%`，说明主模型不稳定。
4. **成本控制**（进阶）：
   - 对简单任务（如分类、短文本摘要）直接用备用模型，不走降级。
   - 在 `LLMService` 里加 `chat_simple` 方法，强制使用便宜模型。

## 第 6 节：常见坑与易错点

### 坑 1：降级后结果质量差，用户投诉

**现象**：主模型（GPT-4）挂了，自动切到备用模型（DeepSeek），结果质量明显下降，用户发现"突然变笨了"。

**原因**：备用模型能力不足，无法完成复杂任务（如多步推理、创意写作）。

**解决**：

- 分级降级：对核心功能（如付费用户请求）不降级，直接返回"服务暂时不可用"；对非核心功能（如免费用户）才降级。
- 在返回时标注："当前使用备用模型，结果可能不如平时精准"。

***

### 坑 2：所有模型同时挂了（雪崩）

**现象**：配置了 3 个模型，但某天全部返回 500 错误，降级失效。

**原因**：多个供应商依赖同一基础设施（如 AWS 区域故障），或同时触发限流。

**解决**：

- 多云部署：主模型用 OpenAI（美国），备用用 Azure OpenAI（欧洲）+ 阿里云百炼（中国）。
- 熔断机制：记录每个模型的连续失败次数，超过阈值（如 5 次）后暂时跳过，避免浪费时间。

***

### 坑 3：备用模型成本更高

**现象**：配置了 GPT-4 作主模型，Claude Opus 作备用，结果发现备用模型更贵。

**原因**：降级策略默认按优先级，不考虑成本。

**解决**：

- 备用模型必须是成本更低的，例如：GPT-4 → GPT-3.5 → DeepSeek。
- 或在 `ModelConfig` 里加 `cost_per_1k_tokens` 字段，排序时考虑成本。

***

### 坑 4：适配器没统一超时，降级反而变慢

**现象**：主模型响应慢（30 秒超时），等它失败后才切备用，总耗时超过 1 分钟。

**原因**：每个模型的超时时间不统一，累加后总耗时过长。

**解决**：

```python
async def chat(self, prompt: str, timeout: float = 10.0) -> dict:
    for model_config, adapter in zip(self.models, self.adapters):
        try:
            result = await asyncio.wait_for(
                adapter.chat(prompt, model=model_config.model),
                timeout=timeout  # 统一超时
            )
            return {"result": result, "success": True, ...}
        except asyncio.TimeoutError:
            print(f"⏱️ {model_config.provider} 超时，尝试下一个")
            continue
```

***

### "和我直觉相反"的提示

**直觉**：降级会增加复杂度，小项目不需要。\
**实际**：即使小项目，主模型故障时完全不可用也很致命；加一个 DeepSeek 备用只需 5 行配置，性价比极高。

**直觉**：抽象层会降低性能。\
**实际**：薄抽象层（只封装接口差异）的性能开销可忽略（< 1ms），但带来的灵活性价值巨大（切换模型从改 100 处代码降到改 1 行配置）。

### 题 3：组合应用（实战）

场景：你的 AI 客服系统每天处理 10 万次对话，要求：

1. 主模型用 GPT-4（质量高但贵，\$0.03/1K tokens）。
2. 备用模型用 DeepSeek（便宜，\$0.001/1K tokens）。
3. 预算：每月 \$3000。
4. 主模型可用性 99.5%（即 0.5% 请求会失败需要降级）。

问题：

1. 如果不用降级，主模型故障时会影响多少用户？
2. 如果用降级，每月成本会增加多少？（假设平均每次对话 500 tokens）
3. 设计降级策略时，需要考虑哪些监控指标？

**答案位置**：

1. 第 2 节痛点（服务雪崩）。
2. 第 5 节成本计算：`降级成本 = 总请求数 × 0.5% × 500 tokens / 1000 × $0.001`。
3. 第 5 节监控指标（`fallback_rate`、`model_used` 统计）+ 第 6 节坑 2（熔断机制）。

## 附录：延伸阅读

- **高级降级策略**：熔断器模式（Circuit Breaker）、基于响应时间的动态切换、金丝雀发布（灰度切模型）。
- **成本优化**：Prompt 缓存（OpenAI/Anthropic 支持）、流式响应减少超时、多模型 A/B 测试。
- **抽象层进阶**：支持流式输出、工具调用（Function Calling）、多轮对话的统一抽象。
- **开源工具**：LangChain 的 `ChatOpenAI` / `ChatAnthropic`（已实现适配器）、LiteLLM（100+ 模型统一接口）。
