# 长文本处理与输出质量校验 - 入门教程

## 第 1 节：它是什么（一句话 + 一句类比）

**长文本处理**：把超过 LLM 上下文长度限制的文档切分成多个小块，分别处理后合并结果，常用 map-reduce 模式（先并行处理各块，再汇总）。

**输出质量校验**：用 schema 验证 LLM 输出格式，失败时自动重试，最多 N 次，保证返回的 JSON/结构化数据符合预期。

**类比**：
- 长文本处理像吃一整只烤鸭——一口吃不下，切成小块（分块），每块单独吃（map），最后拼成"吃完了一只鸭"的结论（reduce）。
- 输出质量校验像工厂质检员——产品（LLM 输出）不合格（格式错误）就退回重做，最多给 3 次机会，还不行就报废。

## 第 2 节：它解决什么问题 / 为什么需要它

### 不处理长文本会怎样？

假设你要摘要一篇 10 万字的论文，直接塞进 LLM：

```python
async def summarize(text: str) -> str:
    prompt = f"Summarize this:\n\n{text}"  # 10 万字直接拼接
    return await llm.chat(prompt)
```

**痛点**：
1. **直接报错**：GPT-3.5 上下文长度 16K tokens（约 1.2 万汉字），10 万字直接超限，返回 `context_length_exceeded` 错误。
2. **信息丢失**：即使用 GPT-4 Turbo（128K tokens），模型也会"注意力涣散"，中间部分内容被忽略（Lost in the Middle 现象）。
3. **成本爆炸**：处理 10 万字一次性消耗 10 万 tokens，即使模型支持，成本也极高（GPT-4 Turbo 约 $1/次）。

**问题根源**：把 LLM 当成"无限容量的黑洞"，忽略了上下文窗口限制。

---

### 不校验输出格式会怎样？

假设你要求 LLM 返回 JSON，但不做校验：

```python
async def extract_info(text: str) -> dict:
    prompt = f"Extract name, age, email from:\n{text}\nReturn JSON."
    response = await llm.chat(prompt)
    return json.loads(response)  # 直接解析，没有校验
```

**痛点**：
1. **格式随机**：LLM 有时返回 `{"name": "John", "age": 30}`，有时返回 `Name: John\nAge: 30`（纯文本），`json.loads` 直接崩溃。
2. **字段缺失**：要求返回 `name, age, email`，实际只返回 `name, age`，下游代码访问 `result["email"]` 触发 `KeyError`。
3. **类型错误**：要求 `age` 是数字，LLM 返回 `"30"`（字符串），数值计算出错。
4. **幻觉数据**：LLM 编造不存在的信息（如原文没提到邮箱，它返回 `email: "unknown@example.com"`）。

**问题根源**：LLM 输出是概率性的，不保证格式正确，业务代码没有防御机制。

---

### 经典应用场景

- **长文本处理**：论文摘要、法律文书分析、客服对话记录归档、整本书的内容提取。
- **输出质量校验**：数据提取（姓名/地址/金额）、结构化知识库构建、API 响应格式保证。

## 第 3 节：读下去之前，先搞懂这些概念

| 术语 | 大白话解释 | 最小示例 | 对应章节 |
|------|-----------|----------|---------|
| Tokenizer | 把文本转成 token 序列，用于计算长度（中文 1 字≈1.5 tokens） | `len(tokenizer.encode("你好"))` | 示例 1 |
| 分块（Chunking） | 把长文本按 token 数切成固定大小的片段 | `chunks = split_text(text, 1000)` | 示例 1 |
| Overlap | 相邻块之间重叠部分，避免关键信息被切断 | `chunk2 = text[800:1800]`（200 重叠） | 示例 1 |
| Map-Reduce | 先对各块并行处理（map），再汇总结果（reduce） | `map: 摘要各章 → reduce: 合并成总摘要` | 示例 2 |
| Pydantic Model | 定义数据结构的 schema，自动校验类型和必填字段 | `class User(BaseModel): name: str` | 示例 3 |
| 重试（Retry） | 操作失败后自动重新执行，最多 N 次 | `for i in range(3): try ... except ...` | 示例 3 |

**术语速查表**：如果你熟悉字符串处理和 Pydantic，可以直接跳到第 4 节。

## 第 4 节：从最简单的代码示例开始

### 示例 1：最小可运行版本 - 固定大小分块

```python
import tiktoken  # OpenAI 官方 tokenizer 库

def split_text_simple(text: str, chunk_size: int = 1000, overlap: int = 100) -> list[str]:
    """
    按 token 数分块，支持重叠
    chunk_size: 每块最大 token 数
    overlap: 相邻块重叠的 token 数
    """
    # 1. 初始化 tokenizer（GPT-3.5/4 用 cl100k_base）
    tokenizer = tiktoken.get_encoding("cl100k_base")
    
    # 2. 把文本转成 token 列表
    tokens = tokenizer.encode(text)
    
    # 3. 如果不超长，直接返回
    if len(tokens) <= chunk_size:
        return [text]
    
    # 4. 滑动窗口切分
    chunks = []
    start = 0
    while start < len(tokens):
        # 当前块：从 start 开始，取 chunk_size 个 tokens
        end = min(start + chunk_size, len(tokens))
        chunk_tokens = tokens[start:end]
        
        # 解码回文本
        chunk_text = tokenizer.decode(chunk_tokens)
        chunks.append(chunk_text)
        
        # 下一块起点：当前终点 - overlap（实现重叠）
        start = end - overlap
        
        # 如果剩余不足 overlap，直接跳到末尾（避免死循环）
        if end == len(tokens):
            break
    
    return chunks

# 使用示例
long_text = "这是一篇很长的文章..." * 1000  # 模拟长文本
chunks = split_text_simple(long_text, chunk_size=500, overlap=50)
print(f"切分成 {len(chunks)} 块，第一块前 50 字：{chunks[0][:50]}")
```

**逐段解读**：

1. **Tokenizer 初始化**：
   - `tiktoken.get_encoding("cl100k_base")`：OpenAI GPT-3.5/4 的分词器。
   - 不能用 `len(text)` 计算长度，因为中文字符 ≠ token 数（"你好"是 2 字但可能是 3 tokens）。

2. **Token 编码**：
   - `tokenizer.encode(text)`：返回 token ID 列表，如 `[1234, 5678, ...]`。
   - 长度判断：`len(tokens) <= chunk_size` 时无需分块。

3. **滑动窗口切分**：
   - 每次取 `chunk_size` 个 tokens，解码回文本。
   - `start = end - overlap`：下一块从当前块末尾往回退 `overlap` 个 tokens，实现重叠。
   - **重叠的作用**：避免关键信息被切断（如"根据第三章结论"被切成"根据第三章" | "结论"）。

4. **边界处理**：
   - `end = min(start + chunk_size, len(tokens))`：最后一块可能不足 chunk_size。
   - `if end == len(tokens): break`：到达末尾时停止。

**这一步你得到了什么**：把 10 万字文本切成 200 个 500-token 的块，相邻块有 50 tokens 重叠。

### 示例 2：加一个真实小需求 - Map-Reduce 式摘要

```python
import asyncio

async def summarize_chunk(chunk: str, chunk_index: int) -> str:
    """对单个块生成摘要（map 步骤）"""
    prompt = f"Summarize the following text (part {chunk_index}):\n\n{chunk}"
    summary = await llm.chat(prompt)  # 调用 LLM
    return summary

async def summarize_long_text(text: str, chunk_size: int = 2000) -> str:
    """
    长文本摘要：分块 + map-reduce
    """
    # 1. 分块
    chunks = split_text_simple(text, chunk_size=chunk_size, overlap=200)
    print(f"📄 文本切分成 {len(chunks)} 块")
    
    # 2. Map 阶段：并行处理各块（生成各块摘要）
    map_tasks = [
        summarize_chunk(chunk, i+1) 
        for i, chunk in enumerate(chunks)
    ]
    chunk_summaries = await asyncio.gather(*map_tasks)
    print(f"✅ 完成各块摘要，共 {len(chunk_summaries)} 段")
    
    # 3. Reduce 阶段：合并所有块的摘要
    combined = "\n\n".join([
        f"Part {i+1}: {summary}" 
        for i, summary in enumerate(chunk_summaries)
    ])
    
    # 4. 如果合并后的摘要仍然很长，递归再摘要一次
    if len(combined) > 5000:  # 假设 5000 字为阈值
        print(f"🔄 合并后摘要仍有 {len(combined)} 字，递归摘要")
        final_summary = await summarize_long_text(combined, chunk_size=2000)
    else:
        # 最终汇总
        final_prompt = f"Generate a final summary from these part summaries:\n\n{combined}"
        final_summary = await llm.chat(final_prompt)
    
    return final_summary

# 使用示例
long_article = "..." * 10000  # 10 万字文章
final_summary = await summarize_long_text(long_article, chunk_size=2000)
print(f"最终摘要：{final_summary[:200]}...")
```

**逐段解读**：

1. **Map 阶段**：
   - `summarize_chunk` 对每个块生成摘要，注意传入 `chunk_index` 让 LLM 知道这是第几部分。
   - `asyncio.gather` 并行处理所有块，速度快（20 个块并发，比串行快 20 倍）。

2. **Reduce 阶段**：
   - 把各块摘要拼成一个文本：`Part 1: xxx\n\nPart 2: yyy`。
   - 检查合并后长度，如果仍超长，**递归调用自己**再摘要一次（这是关键技巧）。

3. **递归终止条件**：
   - 合并后的文本长度 < 5000 字，直接让 LLM 生成最终摘要。
   - 递归最多几层？假设每次摘要压缩 10 倍，10 万字 → 1 万字 → 1000 字，2 层即可。

4. **关键设计**：
   - 分块大小 `chunk_size=2000`：足够让 LLM 理解上下文，又不超模型限制。
   - 重叠 `overlap=200`：防止信息断裂。

**这一步你得到了什么**：处理 10 万字文本，自动分块、并行摘要、递归汇总，最终输出 500 字精炼摘要。

### 示例 3：贴近项目的样子 - 带质量校验的结构化提取

```python
from pydantic import BaseModel, Field, ValidationError
from typing import Optional

# 定义输出 schema
class PersonInfo(BaseModel):
    """人员信息提取结果"""
    name: str = Field(..., description="姓名")
    age: Optional[int] = Field(None, ge=0, le=150, description="年龄，0-150 之间")
    email: Optional[str] = Field(None, description="邮箱地址")
    phone: Optional[str] = Field(None, description="电话号码")
    
    class Config:
        # 严格模式：不允许额外字段
        extra = "forbid"

async def extract_with_retry(
    text: str, 
    schema: type[BaseModel], 
    max_retries: int = 3
) -> dict:
    """
    带重试的结构化提取
    """
    prompt_template = """
Extract information from the following text and return VALID JSON matching this schema:
{schema_json}

Text:
{text}

Return ONLY the JSON object, no explanation.
"""
    
    # 生成 schema 说明（让 LLM 知道要返回什么格式）
    schema_json = schema.schema_json(indent=2)
    prompt = prompt_template.format(schema_json=schema_json, text=text)
    
    last_error: Optional[str] = None
    
    for attempt in range(1, max_retries + 1):
        try:
            # 1. 调用 LLM
            response = await llm.chat(prompt)
            print(f"尝试 {attempt}: 收到响应 {response[:100]}...")
            
            # 2. 解析 JSON
            try:
                data = json.loads(response)
            except json.JSONDecodeError as e:
                raise ValueError(f"无效 JSON: {str(e)}")
            
            # 3. Pydantic 校验
            validated = schema(**data)  # 自动校验类型、必填、范围
            
            print(f"✅ 校验通过！使用尝试次数: {attempt}")
            return {
                "success": True,
                "data": validated.dict(),
                "attempts": attempt
            }
        
        except (ValueError, ValidationError) as e:
            last_error = str(e)
            print(f"❌ 尝试 {attempt} 失败: {last_error[:100]}")
            
            # 如果不是最后一次，修改 prompt 加入错误信息
            if attempt < max_retries:
                prompt += f"\n\nPrevious attempt failed: {last_error}\nPlease fix and return valid JSON."
                await asyncio.sleep(1)  # 短暂延迟
            else:
                break
    
    # 所有重试都失败
    return {
        "success": False,
        "data": None,
        "attempts": max_retries,
        "error": last_error
    }

# 使用示例
text = """
张三，今年 28 岁，目前在阿里巴巴工作。
他的邮箱是 zhangsan@example.com，手机号 13800138000。
"""

result = await extract_with_retry(text, PersonInfo, max_retries=3)

if result["success"]:
    print(f"提取成功: {result['data']}")
    # {'name': '张三', 'age': 28, 'email': 'zhangsan@example.com', 'phone': '13800138000'}
else:
    print(f"提取失败: {result['error']}")
```

**逐段解读**：

1. **Pydantic Schema 定义**：
   - `Field(..., description="xxx")`：`...` 表示必填，`description` 会传给 LLM 作为提示。
   - `ge=0, le=150`：数值范围约束，年龄必须 0-150。
   - `Optional[str]`：可选字段，允许 `None`。
   - `extra = "forbid"`：拒绝多余字段，防止 LLM 乱加字段。

2. **Prompt 构造**：
   - `schema.schema_json()`：自动生成 JSON Schema 描述，让 LLM 知道返回格式。
   - 示例输出：
     ```json
     {
       "name": {"type": "string", "description": "姓名"},
       "age": {"type": "integer", "minimum": 0, "maximum": 150}
     }
     ```

3. **三层校验**：
   - **JSON 解析**：`json.loads(response)`，失败抛 `JSONDecodeError`。
   - **Pydantic 校验**：`schema(**data)`，自动检查类型、必填、范围。
   - **错误反馈**：失败后把错误信息拼到 prompt 里，让 LLM 知道哪里错了。

4. **重试逻辑**：
   - 最多 3 次尝试，每次失败后修改 prompt 加入错误信息（这是关键：让 LLM 自我修正）。
   - 成功立即返回，失败记录尝试次数。

**这一步你得到了什么**：一个生产级的结构化提取函数，自动校验、自动重试、错误反馈，保证输出格式正确。

## 第 5 节：最小可用的实际用法（生产场景模板）

以下是在真实项目中集成的完整示例：

```python
# text_processor.py - 长文本处理服务（必须）
from langchain_text_splitters import RecursiveCharacterTextSplitter  # 推荐用成熟库

class LongTextProcessor:
    """长文本处理器：分块 + map-reduce"""
    
    def __init__(self, llm_service, chunk_size: int = 2000, chunk_overlap: int = 200):
        # 使用 langchain 的分块器（比手写更健壮）
        self.splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=chunk_overlap,
            length_function=self._count_tokens,  # 自定义 token 计数
            separators=["\n\n", "\n", "。", ".", " ", ""]  # 优先在段落/句子边界切分
        )
        self.llm = llm_service
    
    def _count_tokens(self, text: str) -> int:
        """统一的 token 计数（必须）"""
        tokenizer = tiktoken.get_encoding("cl100k_base")
        return len(tokenizer.encode(text))
    
    async def summarize(self, text: str) -> str:
        """长文本摘要（必须）"""
        chunks = self.splitter.split_text(text)
        
        if len(chunks) == 1:
            # 不超长，直接摘要
            return await self.llm.chat(f"Summarize:\n{text}")
        
        # Map: 各块摘要
        summaries = await asyncio.gather(*[
            self.llm.chat(f"Summarize part {i+1}:\n{chunk}")
            for i, chunk in enumerate(chunks)
        ])
        
        # Reduce: 合并摘要
        combined = "\n".join(summaries)
        return await self.llm.chat(f"Final summary from:\n{combined}")

# schema_extractor.py - 结构化提取服务（必须）
from tenacity import retry, stop_after_attempt, wait_fixed  # 推荐用专业重试库

class SchemaExtractor:
    """带校验的结构化提取器"""
    
    def __init__(self, llm_service):
        self.llm = llm_service
    
    @retry(stop=stop_after_attempt(3), wait=wait_fixed(1))  # 自动重试装饰器
    async def extract(self, text: str, schema: type[BaseModel]) -> BaseModel:
        """
        提取并校验（必须）
        失败自动重试，最多 3 次
        """
        prompt = f"""
Extract info from text and return JSON matching this schema:
{schema.schema_json(indent=2)}

Text: {text}

Return ONLY valid JSON.
"""
        response = await self.llm.chat(prompt)
        
        # 解析并校验
        data = json.loads(response)  # JSONDecodeError 会触发重试
        return schema(**data)  # ValidationError 会触发重试

# main.py - 使用示例（必须）
processor = LongTextProcessor(llm_service, chunk_size=2000)
extractor = SchemaExtractor(llm_service)

# 场景 1：长文本摘要
long_doc = load_document("10万字论文.txt")
summary = await processor.summarize(long_doc)

# 场景 2：结构化提取
resume_text = "张三，28 岁，Python 工程师..."
person = await extractor.extract(resume_text, PersonInfo)
print(person.name, person.age)  # 类型安全
```

**关键配置说明**：

1. **分块参数**（必须调整）：
   - `chunk_size`：根据模型上下文设置，GPT-3.5 建议 2000 tokens，GPT-4 可到 4000。
   - `chunk_overlap`：一般设为 `chunk_size` 的 10%，如 2000 → 200。
   - `separators`：优先在段落边界切分，避免切断句子。

2. **重试策略**（推荐配置）：
   - 使用 `tenacity` 库的装饰器，比手写 `for` 循环更简洁。
   - `stop_after_attempt(3)`：最多 3 次。
   - `wait_fixed(1)`：每次重试间隔 1 秒。

3. **成本优化**（进阶，可先跳过）：
   - 对简单文本（如 < 500 字），跳过分块直接处理。
   - 缓存各块摘要：相同块（如论文重复引用）不重复计算。
   - 用便宜模型做 map，贵模型做 reduce（如 GPT-3.5 处理各块，GPT-4 汇总）。

4. **质量监控**（进阶）：
   - 记录每次提取的重试次数，统计失败率。
   - 设置告警：如果 `retry > 1` 的比例 > 10%，说明 prompt 或 schema 需要优化。

## 第 6 节：常见坑与易错点

### 坑 1：分块时切断了关键信息

**现象**：切分后的某个块包含"根据上文所述"，但上文不在这个块里，LLM 生成的摘要失真。

**原因**：固定大小切分不考虑语义边界。

**解决**：
- 使用 `RecursiveCharacterTextSplitter`，优先在段落/句子边界切分。
- 设置 `chunk_overlap`（如 200 tokens），保证上下文连续性。
- 或手动按章节/小节切分（如 Markdown 的 `##` 标题）。

---

### 坑 2：Map-Reduce 摘要丢失全局视角

**现象**：原文是"第一章提出问题，第三章解决"，分块摘要后变成"各章独立内容"，失去章节间联系。

**原因**：各块独立处理，LLM 看不到全文结构。

**解决**：
- 在 map 阶段的 prompt 里加提示："This is part X of a multi-part document, focus on key points."
- 在 reduce 阶段明确要求："Identify connections between parts and generate a coherent summary."
- 或第一遍生成全文大纲（只提取标题），再分块详细摘要。

---

### 坑 3：Schema 校验通过但内容是幻觉

**现象**：提取的 JSON 格式完美，但 `email` 字段是 LLM 编造的（原文没提到邮箱）。

**原因**：Pydantic 只校验格式和类型，不校验内容真实性。

**解决**：
- Schema 设计时，非必填字段用 `Optional`，允许 `None`（让 LLM 知道"没有就返回 null"）。
- Prompt 明确要求："If information is not found, return null. Do NOT make up data."
- 增加置信度字段：`confidence: float`，让 LLM 标注自己的确定性（< 0.5 视为不可信）。

---

### 坑 4：重试次数用尽仍失败

**现象**：3 次重试都返回格式错误的 JSON，最终失败。

**原因**：Prompt 描述不清，或 schema 太复杂，LLM 能力不足。

**解决**：
- 简化 schema：复杂嵌套结构拆成多步提取（先提取人员列表，再逐个提取详情）。
- Few-shot 示例：在 prompt 里给 1-2 个正确的输入输出示例。
- 换更强模型：如 GPT-3.5 失败，切换到 GPT-4。

---

### "和我直觉相反"的提示

**直觉**：分块越小越安全（不会超限）。  
**实际**：块太小（< 500 tokens）会导致上下文不足，LLM 理解能力下降；块太大（> 4000 tokens）又可能超限。最优范围 1000-3000 tokens。

**直觉**：重试 prompt 应该完全重写。  
**实际**：只需在原 prompt 后追加错误信息（如"Previous JSON was invalid, fix it"），利用 LLM 的自我修正能力，比重写更高效。
