# 前端最低线：DOM、fetch、EventSource、CSS 布局

> **目标读者**：后端 Python 开发者，能让 AI 生成一个前端页面，但页面出问题时完全不知道从哪下手。
> **前置知识**：会用浏览器，知道 HTML 长什么样。**不需要**任何 JS 基础。
> **学习时长**：约 3 小时。第 3 节 JS 语法速成若你写过任何一门脚本语言可略读；第 6 节必读。
> **本文的性质**：不是学前端，是**买保险**。目标只有一个 —— AI 生成的前端代码你要**能读、能改、能 debug**。到此为止，不要往下扩展。

> **教学锚点**：本文最终产出一个能对接 [sse-流式响应](./sse-流式响应.md) 里 `/stream` 端点的单文件页面，可直接放进骨架的 `static/index.html`。

---

## 1. 它是什么

一句话：**浏览器里的前端 = 三样东西 —— 一棵可以被改的节点树（DOM）、一个能发请求的电话（fetch/EventSource）、一套排版规则（CSS）。**

生活化类比：**一块可插拔的宣传栏**。

- **DOM** 是宣传栏上的**格子和卡片**。每张卡片有编号（`id`），你可以按编号找到它、换掉上面的字、或者再钉一张新卡片上去。
- **fetch / EventSource** 是宣传栏旁边的**电话机**。`fetch` 是打一通电话问一件事、听完答案就挂断；`EventSource` 是拨通一条热线**不挂断**，对方有新消息就念一句给你听。
- **CSS** 是**排版规定**：卡片多宽、之间隔多远、横着排还是竖着摞、字多大。

| 类比里的东西 | 代码里的东西 |
| --- | --- |
| 按编号找到某张卡片 | `document.getElementById("output")` |
| 换掉卡片上的字 | `el.textContent = "新内容"` |
| 往宣传栏再钉一张卡片 | `el.appendChild(newNode)` |
| 有人按门铃就干活 | `btn.addEventListener("click", fn)` |
| 打一通电话问一件事 | `await fetch("/chat")` |
| 拨通热线不挂断 | `new EventSource("/stream")` |
| 排版规定：横着排、隔 8px | `display: flex; gap: 8px;` |

## 2. 它解决什么问题

### 先看不懂前端会怎样

你让 AI 生成了一个聊天页面，跑起来是白屏。你打开文件，看到 120 行 HTML+JS，每一行都认识每一个单词，但不知道**哪一行出了问题**。

于是你的调试方式变成：把整个文件重新贴给 AI，说"它白屏了"。AI 改了 30 行，还是白屏。再贴，再改。循环三轮之后，这个文件已经没人看得懂了。

**痛点 1：报错信息你根本没看见。** 浏览器的错误不打在终端里，而在 F12 的 Console 面板。不知道这件事的人，会一直以为"没有任何报错"。

**痛点 2：分不清是前端问题还是后端问题。** 页面没数据，可能是后端 500，可能是 CORS 被拦，可能是前端选错了节点。不会看 Network 面板，这三种情况在你眼里是同一种。

**痛点 3：改一个颜色都不敢动。** 因为不知道 `class="flex gap-2"` 是什么意思，怕改坏。结果连最小的样式微调都要重新跑一轮 AI。

### 问题根源

一句话：**你缺的不是写前端的能力，是"定位问题在哪一层"的能力** —— 而这个能力只需要四个概念（DOM 怎么找节点、事件怎么绑、请求怎么发、布局怎么排）加两个面板（Console、Network）。

### 经典应用场景

- 给自己的 AI 接口做一个能演示的页面（Upwork 交付、录 demo）
- AI 生成的页面报错时，10 秒内判断出"这是后端的锅"
- 调整生成页面的间距、颜色、宽度，不重新跑 AI

## 3. 前置知识

### 3.1 JS 语法只需要这些

**定义**：JavaScript 是浏览器里唯一能执行的脚本语言。

**大白话**：和 Python 相比，主要差别是"声明变量要写 `const`"和"代码块用大括号"。

```javascript
const name = "abc";        // 常量，不会再改 —— 默认都用这个
let count = 0;             // 变量，之后会改
```

**函数**：

```javascript
const add = (a, b) => a + b;          // 箭头函数，等价于 Python 的 lambda
async function main() { await f(); }  // async/await 和 Python 几乎一样
```

**模板字符串**（相当于 Python 的 f-string，注意是**反引号**）：

```javascript
const msg = `你好 ${name}`;   // 反引号 ` ，不是单引号
```

### 3.2 DOM

**定义**：浏览器把 HTML 解析成的一棵对象树，JS 可以读写它，页面会实时跟着变。

**大白话**：HTML 是死的文本，DOM 是活的对象。你改 DOM，屏幕立刻变。

```javascript
const el = document.getElementById("out");   // 按 id 找到节点
el.textContent = "hello";                    // 改它的文字，屏幕立即更新
```

### 3.3 事件

**定义**：用户的动作（点击、输入、按键）会在节点上触发事件，你注册回调来响应。

**大白话**：和后端的"路由"是一回事 —— 后端是"来了 `/chat` 请求就跑这个函数"，前端是"点了这个按钮就跑这个函数"。

```javascript
btn.addEventListener("click", () => {        // 点击时跑大括号里的代码
  console.log("被点了");
});
```

### 3.4 术语速查表

| 术语 | 一句话 |
| --- | --- |
| DOM | HTML 对应的、可被 JS 修改的对象树 |
| 节点 / element | 树上的一个标签，比如一个 `<div>` |
| `textContent` | 节点里的纯文字，改它最安全 |
| `innerHTML` | 节点里的 HTML 源码，能插标签，但有 XSS 风险 |
| 事件监听 | "发生 X 就执行 Y"的注册 |
| `fetch` | 发一次 HTTP 请求，返回 Promise |
| `EventSource` | 建一条 SSE 长连接，自动按事件回调 |
| CORS | 浏览器的跨域限制，前后端不同端口时会拦请求 |
| Console 面板 | F12 里看 JS 报错和 `console.log` 的地方 |
| Network 面板 | F12 里看每个请求的状态码和响应体的地方 |
| Flex 布局 | 一维排列（一行或一列）的现代布局方式 |

## 4. 三个递进示例

### 示例 1：最小可运行 —— 点一下，改一个字

新建 `demo.html`，双击用浏览器打开：

```html
<!DOCTYPE html>
<html lang="zh">
<head><meta charset="utf-8"><title>最小示例</title></head>
<body>
  <!-- id 是 JS 找到这个节点的唯一钥匙，全页面不能重复 -->
  <button id="btn">点我</button>
  <div id="out">还没点</div>

  <!-- script 放在 body 末尾：保证执行时上面的节点已经存在 -->
  <script>
    // 按 id 拿到节点对象。拿不到会返回 null，不会报错 —— 这点很坑，见第 6 节
    const btn = document.getElementById("btn");
    const out = document.getElementById("out");

    // 注册事件：点击 btn 时执行第二个参数这个函数
    btn.addEventListener("click", () => {
      // 改 textContent，屏幕上的字立刻变。用 textContent 而不是 innerHTML 更安全
      out.textContent = "被点了 " + new Date().toLocaleTimeString();
    });
  </script>
</body>
</html>
```

**逐段解读**

- `id="btn"`：这是 JS 和 HTML 之间唯一的连接点。看 AI 生成的代码时，**第一件事就是核对 JS 里的 id 和 HTML 里的 id 是否一致**——白屏 bug 有一半出在这。
- `<script>` 放在 `</body>` 前：HTML 是从上往下解析的。如果 script 放在 `<head>`，执行时 `<button>` 还不存在，`getElementById` 返回 `null`。
- `addEventListener("click", () => {...})`：第一个参数是事件名，第二个是回调。注意传的是**函数本身**，不是调用结果——写成 `addEventListener("click", fn())` 是常见错误。
- `out.textContent = ...`：赋值即渲染，不需要"刷新"。

**验证**：打开页面，按 F12 切到 **Console** 面板（这是你今后调前端的主战场），点按钮，文字应该变成当前时间。

**这一步你得到了什么**：你已经掌握了前端的全部骨架——**找节点、绑事件、改内容**。剩下的都是在这三步上加东西。

### 示例 2：加真实需求 —— 调后端接口拿数据

现在让页面去调你的 FastAPI `/chat`。

```html
<script>
  const btn = document.getElementById("btn");
  const out = document.getElementById("out");
  const input = document.getElementById("prompt");

  // 回调写成 async，里面才能用 await
  btn.addEventListener("click", async () => {
    out.textContent = "请求中...";     // 先给用户反馈，别让界面死着
    btn.disabled = true;               // 禁用按钮，防止用户狂点发出 10 个请求

    try {
      const resp = await fetch("http://127.0.0.1:8000/chat", {
        method: "POST",
        // 不写这个头，FastAPI 收不到 JSON body，会返回 422
        headers: { "Content-Type": "application/json" },
        // body 必须是字符串，不能直接传对象
        body: JSON.stringify({ prompt: input.value }),
      });

      // 关键：fetch 遇到 404 / 500 不会抛异常，只是 resp.ok === false。
      // 不手动检查的话，下面 resp.json() 会因为解析错误报一个看不懂的错
      if (!resp.ok) {
        throw new Error(`后端返回 ${resp.status}`);
      }

      const data = await resp.json();   // 再 await 一次，才拿到解析后的对象
      out.textContent = data.reply;
    } catch (err) {
      // 网络不通、CORS 被拦、上面主动抛的错，都会走到这里
      out.textContent = "出错了：" + err.message;
      console.error(err);               // 详细栈打到 Console，方便自己排查
    } finally {
      btn.disabled = false;             // 无论成败都恢复按钮
    }
  });
</script>
```

**逐段解读**

- `async () => {}` + `await fetch(...)`：和 Python 的 `async/await` 语义一致。
- `JSON.stringify({...})`：`body` 只接受字符串，直接传对象会被转成 `"[object Object]"`，后端收到一坨垃圾。
- **`if (!resp.ok) throw`**：这是 fetch 最反直觉的设计——**HTTP 错误码不算失败**。只有网络断了、域名解析不了才会 reject。不写这个检查，你的 500 错误会伪装成"JSON 解析失败"。
- `await resp.json()`：注意有**两次 await**。第一次等响应头，第二次等 body 读完并解析。
- `btn.disabled = true/false` + `finally`：防重复提交。AI 生成的代码经常漏掉 `finally`，导致一报错按钮就永久禁用。

**跨域怎么办**：如果页面是 `file://` 或 `http://localhost:5500` 打开，而后端在 `127.0.0.1:8000`，浏览器会拦下请求，Console 里出现 `blocked by CORS policy`。后端加一行即可：

```python
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["*"], allow_headers=["*"])
```

**这一步你得到了什么**：能把后端接口接到页面上，并且**知道出错时去 Console 看什么、去 Network 看什么**。这就是"分层定位"能力。

### 示例 3：贴近项目 —— 流式输出页面

`fetch` 是"问一句答一句"，流式输出要用 `EventSource`（对应 [sse-流式响应](./sse-流式响应.md) 的 `/stream`）。

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <title>流式演示</title>
  <style>
    /* 容器：竖着排（column），每个子元素之间空 12px */
    body { display: flex; flex-direction: column; gap: 12px;
           max-width: 720px;      /* 内容不超过 720px 宽，大屏上不至于一行拉太长 */
           margin: 40px auto;     /* 上下 40px，左右 auto = 水平居中 */
           font-family: system-ui, sans-serif; }

    /* 这一行是横着排的：输入框 + 两个按钮 */
    .row { display: flex; gap: 8px; }

    /* flex:1 = 剩下的宽度全给我。这样按钮宽度不变、输入框自动撑满 */
    #prompt { flex: 1; padding: 8px; }

    #out { min-height: 200px; padding: 12px;
           border: 1px solid #ddd; border-radius: 6px;
           white-space: pre-wrap;   /* 关键：保留模型输出里的换行和空格，否则全挤成一行 */
           line-height: 1.6; }
  </style>
</head>
<body>
  <div class="row">
    <input id="prompt" placeholder="问点什么">
    <button id="send">发送</button>
    <button id="stop" disabled>停止</button>
  </div>
  <div id="out"></div>

  <script>
    const $ = (id) => document.getElementById(id);   // 少打点字的小工具
    const out = $("out"), send = $("send"), stop = $("stop"), prompt = $("prompt");

    let es = null;   // 保存当前连接，停止按钮和清理逻辑都要用到

    // 统一的收尾：关连接 + 恢复按钮状态。多处调用，抽出来避免漏改
    function finish() {
      if (es) { es.close(); es = null; }
      send.disabled = false;
      stop.disabled = true;
    }

    send.addEventListener("click", () => {
      if (es) es.close();        // 上一条连接还开着就先关，否则会同时开两条
      out.textContent = "";      // 清空上次结果
      send.disabled = true;
      stop.disabled = false;

      // EventSource 只支持 GET，参数只能放 URL 上。
      // encodeURIComponent 处理中文和 & 等特殊字符，不加会导致参数截断
      const url = `/stream?prompt=${encodeURIComponent(prompt.value)}`;
      es = new EventSource(url);

      // 默认事件：后端 yield 的不带 event: 字段的那些
      es.onmessage = (e) => {
        const data = JSON.parse(e.data);    // 后端发的是 JSON 字符串
        out.textContent += data.delta;      // += 追加，这就是"逐字出现"的效果
      };

      // 后端 yield 了 event: done，这里按名字单独监听
      es.addEventListener("done", () => finish());

      // 后端主动发的业务错误（event: error）
      es.addEventListener("error", (e) => {
        // 注意：这个名字同时也是浏览器的连接错误事件，所以要区分
        // e.data 存在 = 后端发来的业务错误；不存在 = 连接层断了
        out.textContent += e.data ? `\n[错误] ${JSON.parse(e.data).message}` : "\n[连接中断]";
        finish();   // 必须关！否则 EventSource 会自动重连，把错误请求无限重放
      });

      stop.addEventListener("click", finish, { once: true });
    });
  </script>
</body>
</html>
```

**逐段解读**

- `let es = null` 放在外层：因为"停止"按钮和 `finish()` 都要访问同一个连接对象，必须是共享变量。
- `if (es) es.close()`：不关旧连接就点第二次，会同时有两条流往同一个 div 写字，输出会交错成乱码。
- `encodeURIComponent`：prompt 里有中文、空格、`&` 时不转义会导致后端收到的参数被截断。
- `out.textContent += data.delta`：`+=` 是流式效果的全部秘密——每来一小段就往后接。
- **`addEventListener("error", ...)` 里必须 `close()`**：`EventSource` 的设计是**断了自动重连**。后端报 500 你不关，浏览器会每 3 秒重发一次，把一个失败请求变成一场 DDoS（打你自己的服务器）。这是最贵的一个坑。
- `white-space: pre-wrap`：模型输出的换行默认会被 HTML 折叠成空格，加这行才能保留格式。

**CSS 你只需要记这几个**：

| 属性 | 作用 | 什么时候改 |
| --- | --- | --- |
| `display: flex` | 让子元素排成一行 | 想横着排东西 |
| `flex-direction: column` | 改成竖着排 | 想竖着摞 |
| `gap: 8px` | 子元素之间的间距 | 觉得太挤/太散 |
| `flex: 1` | 这个元素占满剩余空间 | 输入框想自动撑满 |
| `padding` / `margin` | 内边距 / 外边距 | 觉得字贴边了（padding）、块之间太近了（margin） |
| `max-width` + `margin: auto` | 限宽 + 居中 | 大屏上一行太长 |

**这一步你得到了什么**：一个能展示流式输出、能停止、能显示错误的完整页面。而且这些 CSS 属性足够你改动 AI 生成页面里 90% 的样式问题。

## 5. 最小可用的实际用法

把下面这个文件存成 `static/index.html`，在 FastAPI 里挂载即可（前后端同源，**不用配 CORS**）：

```python
# app/main.py
from fastapi.staticfiles import StaticFiles

# html=True 让访问 / 时自动返回 index.html
app.mount("/", StaticFiles(directory="static", html=True), name="static")
# 注意：这行必须放在所有 API 路由定义之后，否则会把 /health 等路由吃掉
```

页面骨架（必须的行已标注）：

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="utf-8">                              <!-- 必须：不加中文乱码 -->
  <style>
    body { max-width: 720px; margin: 40px auto; font-family: system-ui; }
    .row { display: flex; gap: 8px; }                 <!-- 可选：只是好看 -->
    #prompt { flex: 1; padding: 8px; }
    #out { min-height: 200px; padding: 12px; border: 1px solid #ddd;
           white-space: pre-wrap; }                   <!-- 必须：保留换行 -->
  </style>
</head>
<body>
  <div class="row">
    <input id="prompt" placeholder="问点什么">        <!-- 必须：id 要和 JS 对上 -->
    <button id="send">发送</button>
  </div>
  <div id="out"></div>

  <script>                                            <!-- 必须：放 body 末尾 -->
    const out = document.getElementById("out");
    let es = null;

    document.getElementById("send").addEventListener("click", () => {
      if (es) es.close();                             // 必须：防止多连接并发
      out.textContent = "";
      const p = document.getElementById("prompt").value;
      es = new EventSource(`/stream?prompt=${encodeURIComponent(p)}`);  // 必须：转义

      es.onmessage = (e) => { out.textContent += JSON.parse(e.data).delta; };
      es.addEventListener("done", () => { es.close(); es = null; });    // 必须：收尾
      es.addEventListener("error", () => { es.close(); es = null; });   // 必须：防重连风暴
    });
  </script>
</body>
</html>
```

**可以跳过的进阶项**：

- **框架（React / Vue）**：不需要。一个演示页面用原生 JS 20 行就够，引入框架要配构建工具，收益为负。跳过。
- **Tailwind / UI 组件库**：AI 生成的页面常带 Tailwind 的 `class="flex gap-2 px-4"`。你只要知道这些 class 名基本就是 CSS 属性的缩写（`gap-2` ≈ `gap: 8px`），能看懂就行，不用学。
- **手动实现 SSE 重连、`Last-Event-ID`**：`EventSource` 自带重连。跳过。
- **用 `fetch` + `ReadableStream` 做流式**：只有需要 POST 大 body 时才必要（`EventSource` 只支持 GET）。先用 GET，撑不住了再说。跳过。

## 6. 常见坑与易错点

### 坑 1：页面白屏 / 按钮点了没反应

**报错原文**（Console 里）：`Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')`

**原因**：`getElementById` 没找到节点，返回了 `null`。两种可能：① JS 里的 id 和 HTML 里的对不上（AI 改代码时最容易改漏一边）；② `<script>` 放在了 `<head>` 里，执行时节点还没被解析出来。

**解决**：核对 id 拼写；把 `<script>` 移到 `</body>` 之前。

---

### 坑 2：请求发不出去，Console 里一片红

**报错原文**：`Access to fetch at 'http://127.0.0.1:8000/chat' from origin 'http://localhost:5500' has been blocked by CORS policy`

**原因**：端口不同就算跨域，浏览器主动拦截。**这是浏览器拦的，不是后端拒绝的**——后端日志里可能连这个请求都没有。

**解决**：最优解是把页面用 `StaticFiles` 挂到 FastAPI 上（同源，问题消失）；开发期临时方案是加 `CORSMiddleware`。

---

### 坑 3：后端 500 了，前端却说"JSON 解析失败"

**报错原文**：`SyntaxError: Unexpected token '<', "<html>..." is not valid JSON`

**原因**：`fetch` **不会**因为 4xx/5xx 抛异常。你没检查 `resp.ok` 就直接 `resp.json()`，而后端返回的是 HTML 错误页，解析自然失败。报错信息完全指向错误的方向。

**解决**：`fetch` 之后**永远**先写 `if (!resp.ok) throw new Error(resp.status)`。

---

### 坑 4：EventSource 报错后无限重连

**现象**：后端日志里同一个请求每 3 秒出现一次，一直不停；关掉页面才停。

**原因**：`EventSource` 的规范行为就是断线自动重连，而且默认永不放弃。后端返回 500 → 连接断 → 3 秒后重连 → 又 500 → 循环。

**解决**：`onerror` 回调里**必须**调 `es.close()`。这也是第 5 节把它标成"必须"的原因。

---

### 坑 5：模型输出的换行全没了，挤成一坨

**现象**：后端明明发了带 `\n` 的 markdown，页面上显示成一整行。

**原因**：HTML 默认把连续空白（包括换行）折叠成一个空格。

**解决**：给输出容器加 `white-space: pre-wrap;`。

---

### 和直觉相反的一点

**改了 HTML/CSS 刷新页面，看到的还是旧的。**

浏览器会缓存静态文件。你改了 `index.html` 按 F5，很可能加载的还是缓存里的旧版本——于是你以为"我的改动没生效"，开始怀疑代码，其实代码是对的。

**解决**：F12 打开 DevTools，Network 面板勾上 **Disable cache**（只在 DevTools 打开时生效），或者用 `Ctrl + Shift + R` 强制刷新。

**养成习惯：调前端时 F12 一直开着。** 它同时解决了看报错（Console）、看请求（Network）、禁缓存三件事。
